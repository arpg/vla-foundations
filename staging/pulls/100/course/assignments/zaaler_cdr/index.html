Capstone Design Review — SFT Knowledge Distillation for Robotic EV Battery Disassembly

Introduction

This project extends the RAPID (Robotic Agentic Platform for Intelligent Disassembly) system submitted to CASE 2026. RAPID uses a SmolAgents CodeAgent to control a gantry-mounted UR16e manipulator for disassembling Hyundai Ioniq5 EV battery packs via ROS MCP tool calls. The CASE paper evaluated GPT-4o-mini, Qwen 3.5 9B, and Qwen 3.5 4B on the task "Remove all remaining parts." GPT-4o-mini and Qwen 3.5 9B succeeded reliably; Qwen 3.5 4B failed in 7/10 trials, removing 0–1 of 5 target parts despite claiming 5 successes. This capstone investigates whether SFT on GPT-4o-mini reasoning traces can close that gap without increasing model size.

Architectural Delta

Bottleneck: The Qwen 3.5 4B model lacks the structured planning depth to reliably sequence multi-step ROS tool invocations via MCP, while larger models succeed — SFT on GPT-4o-mini planning traces transfers that reasoning capability to the 4B model for edge deployment on the Jetson Thor.

The failure is not syntactic. The 4B model produces valid code but skips the logical dependency chain: status → call_service('/remove_part') → mark_removed. GPT-4o-mini and Qwen 9B produce a structured Facts Survey + numbered Plan that correctly sequences all three steps. SFT directly supervises the 4B model on those planning outputs.

Data Mix

Base model: Qwen/Qwen3.5-4B

Task data: 9,139 GPT-4o-mini planning traces, each formatted as a 3-turn chat: system (RAPID robot instructions) → user ("Remove all remaining parts") → assistant (planning trace). Split 90/5/5 into train (8,225) / val (457) / test (458).

General data: 1,452 examples sampled from OpenHermes-2.5 mixed in at 85% task / 15% general. Full fine-tuning on a single-prompt, narrow-distribution dataset risks catastrophic forgetting. The 15% general mixture acts as a regularizer — large enough to preserve general language capability, small enough that the task signal dominates. This ratio reflects standard practice for task-dominant SFT corpora where the primary risk is forgetting, not underfitting.

Implementation Status

Complete: Data pipeline, mixed dataset (85/15 verified), TRL SFTTrainer with auto-resume across sessions, live training monitor with automated divergence and overfitting warnings.

Complete: Full fine-tuning on A100 80GB — converged at 0.5 epochs (4,112 examples), bf16, effective batch size 16, lr 2×10⁻⁵ cosine, eval loss 0.0002.

Critical path: Training → Jetson deployment → evaluation. No current blockers.

The Hard Question

"Your model is trained on 9,139 examples of one task with one prompt. Have you instilled generalizable tool-use reasoning, or just memorized one plan?"

This is the primary scope limitation and is acknowledged. The hypothesis is narrow: SFT on GPT-4o-mini traces enables reliable execution of this specific task on the target hardware. Generalization to new tasks is not claimed. The contribution is a proof-of-concept for task-specific knowledge distillation in robotic manipulation agents — demonstrating that a failing small model can reach parity with a larger model on a target task through planning trace imitation. Generalization experiments are future work.

A training data size ablation study (fractions: 10%, 25%, 50%, 75%, 100% of 4,112 examples) is included to analyze data efficiency — specifically, how much training data is necessary to achieve reliable task performance. The model converged at 4,112 examples (half of the original 8,225 training split), which is treated as the 100% training data level. This establishes a practical baseline for future work: if the approach were extended to new tasks, the ablation curve informs how many traces would need to be collected per task to reach a useful performance threshold.
