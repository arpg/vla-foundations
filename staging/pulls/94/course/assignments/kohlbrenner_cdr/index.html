Critical Design Review

My project is called Humanoid Proximity Dreaming. The objective is to teach a humanoid robot to predict what its onboard proximity sensors will observe in the future so that it can plan safe motions. I plan to teach this model using a world model architecture that encodes the sensor states into a latent vector, then a dynamics model autoregressively predicts what tokens come next.

The Architectural Delta

Can your partner state, in one sentence, what bottleneck you are addressing and why the existing approach fails? If they can't, your framing needs work.

One sentence: Engineering the representation of data used to train a world model to handle sparse proximity images may increase sample efficiency of learning contact-dependent tasks.

One paragraph: Predicting contact with nearby objects is difficult with model-based methods when the nearby objects are highly dynamic. A proximity sensing world model that can dream future observations will be more robust to the dynamics found in data instead of explicit modeling. By training a world model on sequences of low-dimensional proximity images instead of camera images, a contact avoidant policy can be trained effectively on a smaller distribution of trajectories since proximity is the salient feature for contact avoidance.

The Architecture

The architecture of the world model is encoder -> dynamics model -> decoder. The encoder is a 3D VQ-VAE that encodes the full set of sensor images into a single vector. The dynamics model is a transformer that predicts the next latent token in time. The decoder is a 3D VQ-VAE that decodes the predicted latent token back into a set of sensor images.

Final Evaluation

Addressing the Bottleneck from CDR

After discussing at CDR, it became apparent that the model may have been suffering from mode averaging, causing the predicted trajectories to be blurry and inconsistent. The mode averaging is an artifact of the autoregressive dynamics model settling on the average, blurred combination of multiple possible trajectories that the ball could have taken at any moment instead of commiting to a consistent prediction. This mode averaging stems from the cross entropy minimization objective of the dynamics model, which learns a unimodal pdf minimized by KL divergence to cover the full distribution of multi-modal probabilities. Luckily, diffusion and flow matching models are mode seeking and commit to a single trajectory during generation, and the average of a multimodal distribution is an unstable saddle point that needs one forward step to be commital.

Modified Architecture and Loss Formulation

To address the moed averageing behavior, I implemented a flow matching based dynamics model to predict future latent tokens. Unlike image genreation models, this flow matching model is reconstructing latent tokens instead of pixels from a learned noise distribution. Flow matching learns a velocity field that directs the reconstruction from its noisy state via minimizing the MSE between true fields vt=xtarget−z0v_t=x_{target} - z_0vt​=xtarget​−z0​ and the predicted fields vpredv_{pred}vpred​.

LFM=Et, x1∼pdata, ϵ∼N(0,I)∥vθ(xt,t)−x1−xt1−t∥2\mathcal{L}_{FM} = \mathbb{E}_{t,\, x_1 \sim p_{\text{data}},\, \epsilon \sim \mathcal{N}(0,I)} \left\| v_\theta(x_t, t) - \frac{x_1 - x_t}{1 - t} \right\|^2LFM​=Et,x1​∼pdata​,ϵ∼N(0,I)​​vθ​(xt​,t)−1−tx1​−xt​​​2

The previous architecture used a discrete encoder/decoder pair as a VQ-VAE, but vector quantizer was dropped to output a continuous vector. This change introduced increased blur in the predicted sensor frames, so an additional weighting was added to the reconstruction error to prioritize reconstructing low greyscale values (which indicate detection) using the following formula:

Lrecon=1∣Ω∣∑i∈Ωw(xi) ℓ(x^i,xi)\mathcal{L}_{recon} = \frac{1}{|\Omega|}\sum_{i\in\Omega} w(x_i)\,\ell(\hat{x}_i, x_i)Lrecon​=∣Ω∣1​∑i∈Ω​w(xi​)ℓ(x^i​,xi​)

Results

The VAE + FM world model architecture was trained ant tested on a single trajectory, 1000 trajectory, and 10000 trajectory dataset to see if the mode averaging behavior has been resolved.

Single Trajectory: Sanity Check

For the case where the model was overfit to a single trajectory, there really is not much left to improve. There is a clear future predicted trajectory that is consistent and correct for the test case (where predictions are indicated by the blend from green to red pointcloud stichings). This test still hallucinates dramatically as expected when it is prompted to predict what happens after contact since this information was not provided in the data. This single trajectory test mirrors the results achieved by the AR transfromer and VQ-VAE, so next we test on a larger dataset.

1000 Trajectories: A Scaling Nudge

The 1000 trajectory case demonstrates clear improvements in consistency and prediction accuracy. as compared to the 10000 trajectory AR model. There is a clear stream of red pixels hovering over where the ball will be in the future, however, there is also some variance in the predictions causing a spread of point cloud points. This demonstrates that the mode averaging behavior is potentially reduced by the FM mdoel and it chooses a future directio that the ball will likely take and sticks with it. It should be noted that the FM model was bigger in this training run than the AR 10000 trajectory training run due to model differences and a limited training window to test multiple mode sizes.

Future Work

I anticipated that I would be able to train this world model locally on an RTX 4090 because I was only testing in a small, narrow task distribution. However, I quickly realized that the scaling laws for this problem are quite large for even ball path generalization without actions. As I introduce actions into the model, I anticipate that the problem will increase in nonlinearity and sample inefficiency, so future work demands a stronger compute setup such as the CU Alpine cluster. This will be important for a rigorous test between the AR and flow matching based WMs on whether the hallucinations are a result of mode averaging, however, since FM was fairly replacable with AR and realtime prediction is not necessarily needed at this stage, I will stick with FM for now as the project continues.

Additionally, I would like to condition the robot on more examples of objects it could see besides just balls for dodgeball. For example, the dynamics of a human hand may be difficult to estimate through a model based estimation algorithm, but a data-based WM may have a unique advantage at modeling it.
